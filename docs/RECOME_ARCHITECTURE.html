RecoMe, end to end:
your interest graph, working for you.

RecoMe captures what you research across 15 platforms, builds a typed personal interest graph in Neo4j + Qdrant, and runs five background agents on it that surface what you'd otherwise miss — without you ever opening a chat window. Same backend powers a public IaaS API at /v1/*, billed per-signal via Stripe Meters. This document is the canonical reference: thesis, HLD, every module, every flag, every deferred follow-up.

01 · Foundation

Engineering highlights

The decisions that define what RecoMe is, each backed by a section further down that explains the design and the trade-offs.

Chat is not the product→ Thesis

Pivot away from a chat UI to background agents working a typed interest graph. Surfaced through the inbox, the in-page extension overlay, PWA push, and email digest — you almost never have to ask. ADR-0012 + ADR-0013 set the category.

Dual-sided revenue from one backend→ IaaS

Consumer (recome.app, JWT, FREE/PRO/PREMIUM) and IaaS (api.recome.app/v1, rk_live_…, FREE/STARTER/PRO/ENTERPRISE) share one Hono+Prisma+Neo4j stack. Tenant scoping via composeTenantUserId(tenantId, externalUserId); usage billed via Stripe Meters.

Five agents, one envelope→ Agents

Recall · Concierge · Curator · Decision · Curriculum, all gated by a single GuardianAgent enforcing $0.10/user/day LLM cap, per-agent throttle, opt-in pause, and quiet hours. Every emission cites the source signals.

Provider-agnostic CardScorer→ CardScorer

Two-stage per-card badge: deterministic verdict + score (topic-overlap), optional LLM polish of the reasoning prose only. Prompt injections can't flip a "filtered" badge to "relevant" — the LLM never touches policy.

BullMQ scheduled workers, in-process→ Workers

One queue, four cron ticks: Curator daily, Concierge sweep 4×/day, Stripe Meters rollup daily, weekly email digest. Per-user fan-out at concurrency 5 with a 1000-user/tick ceiling. Guardian + dedupe make duplicate ticks idempotent.

PWA push end-to-end→ Push

VAPID-signed web-push fans out on every AgentEvent insert. 410/404 from the provider auto-disables stale subs; service worker uses notification tag to collapse re-delivers; click reuses an open tab on origin.

Three OS share-sheet surfaces→ Mobile

Same /intelligence/signals ingest path serves the browser extension, the web PWA share-target, and a native iOS Share Extension + Android SEND intent. One contract, three OSes, no on-device topic extraction.

Public OpenAPI + Developer dashboard→ IaaS

Hand-rolled OpenAPI 3 at /v1/openapi.json, Swagger UI at /v1/docs. JWT-authed /developer dashboard lets users create tenants and issue rk_live_… keys (shown once, hashed at rest, prefix-only display).

02 · Foundation

System architecture at a glance

Four clients, one Hono edge, six service modules, three data stores, four external providers. The whole product is < 30 modules — the rest is data.

Hono edge fans into per-feature controllers; agent + worker layers share the same data planes. Tenant scoping is the only path branch.
Languages & frameworks

Backend is TypeScript on Node 22, Hono 4 (typed context via Hono<AuthEnv>), Prisma 6. Web is Next 16 + React 19 + Tailwind 4. Extension is MV3 + React 19 popup + shadow-DOM sidebar. Mobile is Expo / React Native 0.76 + native Swift for iOS Share Extension.

Data & state

Postgres (Neon prod, local Docker dev) for OLTP — identity, billing, tenants, agent runs, events. Neo4j AuraDB is the personal interest graph (one namespace per user). Qdrant Cloud for per-user vector namespaces. Redis (Upstash) for BullMQ + rate-limit counters.

External services

OpenAI embeddings + optional polish · Stripe (subs + Meters) · Keepa (Amazon prices, off by default) · web-push (VAPID) · Resend (digests). Each gated by an env var; missing keys downgrade gracefully without crashing.

03 · Foundation

Thesis & positioning

RecoMe's category isn't "AI assistant." It's "personal memory as infrastructure" — the graph is the product, agents work it for you, surfaces deliver the result where you already are.

The product premiseADR-0013

Perplexity Memory and Claude Managed Agents proved the pattern: the future of personal AI is persistent context + autonomous action, not turn-by-turn chat. RecoMe extends that by being cross-platform — the same user gets one graph from YouTube, Reddit, Amazon, Substack, and 11 more, where competitors are siloed to their own walled gardens.

The thesis sentence: "The chat is not the product. The personal interest graph is."

Three durable moatsADR-0014
  • Cross-platform signal density — the extension watches 15 platforms; competitors get 0–1 each.
  • Sourced emissions — every agent output cites the captured signals (F-408 Audit Log of You).
  • Dual-sided distribution — consumer surface drives organic data; IaaS surface monetizes the same graph for builders.
Dual-sided modelADR-0003

Consumer. recome.app + browser extension + mobile + PWA. JWT auth. Tiers FREE / PRO / PREMIUM (Stripe subscription). Persona: Riya, the decision-paralysed researcher running multi-week research across YouTube, Reddit, Amazon.

IaaS. api.recome.app/v1/*. API-key auth (rk_live_…). Tenant-scoped via composeTenantUserId(tenantId, externalUserId). Tiers FREE 1K/10K · STARTER $49/100K · PRO $499/1M · ENTERPRISE. Billed monthly via Stripe + per-signal via Stripe Meters.

What we will not doHLD §11
  • No LLM API keys in the browser.
  • No in-browser graph or agents.
  • No cross-user training (each Neo4j + Qdrant namespace is single-user).
  • No background-pull polling without an explicit user action.
  • No "agent that posts on your behalf" — recommend-only, by ADR-0012 §5.

Canonical end-to-end journey · Riya's standing-desk research→ Pipeline
  1. Capture. Riya watches a Wirecutter video. The extension's YouTubeCapture emits a page_view signal with dwell 184s + entity hints ["Uplift V2", "Fully Jarvis"].
  2. Ingest. Extension batches with the IDB queue, SignalUploader drains every 30s to POST /intelligence/signals. SignalIngestion deterministically extracts topics (standing desks) + entities.
  3. Graph. Neo4j Cypher merges (:User)-[:HAS_INTENT {strength, platformsTouched}]->(:Topic) + per-entity edges. Qdrant gets the topic embedding for similarity.
  4. Agent. Three days later Riya lands on Amazon for "Uplift V2." ConciergeAgent fires via event trigger (fireSignalIngestTrigger); compareOffers() hits Keepa, computes the 10%-below-baseline gate, emits deal_drop.
  5. Surface. AgentEventStore.insert persists with dedupe; fires PushService.notifyUser for VAPID delivery; the extension InboxPoller picks it up on next 2-min alarm; the web /inbox renders it; if Riya hasn't opened the app, it lands in Sunday's Resend digest.

Five guarantees the pipeline upholdsADR-0012 §5
  • Citation, always. Every AgentEvent.sources array is mandatory — emissions without sources are rejected at insert.
  • Recommend, never act. Agents propose; the user clicks actionUrl.
  • Dedupe by intent. Same (userId, dedupeKey) inside 24h is suppressed at AgentEventStore.insert.
  • Guardian-gated. Daily LLM cost cap, per-agent throttle, opt-in pause, quiet hours.
  • Single-user training. Each Neo4j + Qdrant namespace is single-user; nothing trains across users.
06 · Pipeline

Neo4j interest graph

One namespace per user. Topics + entities + signals + sessions + typed edges, with recency-decayed strengths. The "is this user truly into X across platforms?" question reduces to one Cypher MATCH.

Node + relationship modelADR-0001 + 0009
  • (:User) — one root per cuid (consumer) or per tenant_<id>__<ext> (IaaS).
  • (:Topic) — normalized name (lowercased, slug-form) + display name. Globally shared shape, but edges are user-scoped.
  • (:Entity) — products, brands, creators, places, people.
  • (:Signal) — the captured event; correlates back to the Postgres audit log via signalId.
  • (:Session) — per-tab session for correlation.
  • [:HAS_INTENT], [:HAS_ENTITY], [:OBSERVED_ON], [:SEEN_DURING] — typed edges carrying strength, lastTouched, platformsTouched.
Canonical writecloud/src/graph/GraphRepo.ts
MERGE (u:User {id: $userId})
MERGE (t:Topic {normalized: 'distributed-systems'})
ON CREATE SET t.name = 'distributed systems'
MERGE (u)-[r:HAS_INTENT]->(t)
SET r.strength = coalesce(r.strength, 0) + $delta,
    r.lastTouched = $now,
    r.platformsTouched = apoc.coll.toSet(
      coalesce(r.platformsTouched, []) + ['youtube']
    )
RETURN r.strength AS strength

Why this shape: the cross-platform trail (≥2 platforms touched on the same topic edge) is what powers F-401 Mind Map and Recall — a single edge join, not a per-signal aggregate.

Schema migrations
  • Constraints + indexes managed by scripts/migrate.ts (idempotent CREATE CONSTRAINT IF NOT EXISTS patterns).
  • Run on boot only when INTELLIGENCE_RUN_MIGRATIONS_ON_BOOT=true (safe in dev; prod uses npm run graph:migrate).
  • Stale-volume drill: documented Neo4j local recovery via docker volume rm after extended idle.
07 · Pipeline

Qdrant + OpenAI embeddings

One Qdrant collection (recome_v1) with per-user payload namespacing. Embeddings via text-embedding-3-small. Used for topic similarity (Recall, related-topic suggestions, Taste Twin).

Tenancy

Single collection, payload-keyed isolation: every point carries userId. All searches filter by it server-side; a forged userId in client payload never crosses the boundary because the API layer composes it from JWT/API-key auth.

Model + dimensions

text-embedding-3-small, 1536 dims. Cheaper-band than 3-large; quality margin is below noise floor at our retrieval cardinality (top-N=8). Wrapped in OpenAIEmbeddings with a tiny in-process LRU.

Usage path

Ingest → embed topic name → upsert. Query side: Recall similarity match, Decision related-topic suggestions, Taste Twin profile vectors. All wrapped behind QdrantClient so a vendor swap is one file.

AgentRunner lifecyclecloud/src/agents/AgentRunner.ts
  1. canRun(). Cheap pre-check on the agent itself; skip silently if false.
  2. Guardian check. Subscription enabled? Paused? Daily cost cap free? Quiet hours? Per-agent throttle gap met? Capped runs persist as AgentRun with status='capped' for audit.
  3. run(). Agent executes. Errors caught + recorded as failed — never re-thrown, so one bad agent can't poison a request that triggered N agents.
  4. Emit + dedupe. AgentEventStore.insert with (userId, dedupeKey) 24h window. Dropped duplicates still record an AgentRun with suppressed: true.
  5. Push fan-out. Fire-and-forget PushService.notifyUser; failures isolated. Pulled by extension InboxPoller every 2 min as a belt to the push braces.
09 · Agents

Guardian runtime gate

The "sixth agent" — not user-facing, but it decides whether any of the other five run for any given (user, agent, now) triple. ADR-0012 §5 made this the hard floor.

Four constraintscloud/src/agents/GuardianAgent.ts
  • Daily cost cap. $0.10/user/day hard ceiling on summed costMicros from AgentRun in last 24h.
  • Per-agent throttle. Currently Recall ≤ 2/wk (84-hour gap). Concierge / Curator gaps land when shipped.
  • Opt-in / pause. AgentSubscription.enabled = false or pausedAt != null short-circuits.
  • Quiet hours. 22:00–08:00 user-local; suppresses background emissions, doesn't gate on_demand.
Why decisions return as data, not exceptions

Guardian returns { allow: false, status: 'capped', reason: '…' } instead of throwing. The runner records a structured AgentRun with status='capped' + the reason in meta — same audit trail as a real run, so the founder can see why an agent didn't fire when investigating "why didn't Recall surface that?"

The /agents/budget endpoint reads this audit log to render daily-spend bars in the management UI, with the cap pulled from the same DEFAULT_DAILY_COST_CAP_MICROS constant Guardian enforces against.

10 · Agents

Decision SSE streaming

v1 ships word-chunked deterministic streaming so the client protocol is locked in before the LLM swap. POST /intelligence/agents/decision/stream via Hono's streamSSE.

Wire protocol
data: <text-chunk>\n\n             // appended to assistant turn
data: __meta__:{"sources": […]}\n\n  // final envelope
data: [DONE]\n\n                    // close marker

Same protocol works whether the inner loop is chunkByWords() (v1) or an LLM stream (v1.1). Client code at extension/src/surfaces/OverlayChat.ts and web/src/app/ask/page.tsx already consumes it.

Shared compose() pathDecisionAgent.ts

One compose() helper produces a discriminated union: { kind: 'skip' } | { kind: 'ok', title, body, sources, dedupeKey }. Both run() (batch path) and runStream() (SSE path) consume it — no two formattings of the same answer. When the LLM polish ships, the swap is one method.

11 · Agents

CardScorer — per-card badges

Every product on Amazon, every video on YouTube, every post on Reddit gets a coloured badge — relevant / neutral / caution / filtered — grounded in your graph. Provider-agnostic two-stage pipeline.

Two stages, one contractcloud/src/intelligence/CardScorer.ts
  1. Deterministic pre-score. Topic-overlap against the user's top 30 intents. Cheap, runs for every card, never costs LLM tokens. Outputs { score, verdict, reason }.
  2. LLM polish (opt-in). Re-writes reason for top-N eligible cards via one batched call. Verdict + score stay deterministic — the LLM only writes prose grounded in the user's matched topics. Prompt injections can't flip "filtered" to "relevant."
  3. Cost guard. MAX_LLM_CALLS_PER_REQUEST = 10 per POST /intelligence/score/cards. LLM failure degrades silently to deterministic baseline; never blocks page render.
Why "LLM writes prose only" is load-bearing
  • An attacker who controls page content (a card title or brand) cannot get the verdict flipped — the LLM never decides policy.
  • The verdict + score are reproducible from public inputs (intents + card text). The reason is the only thing that varies between deterministic + LLM-polished modes.
  • Provider-swap (OpenAI today, Anthropic Haiku per HLD §4) is one constructor change. CARDSCORER_LLM_ENABLED=false default keeps prod cost predictable.

BullMQ scheduled workers

One queue, four cron-scheduled tick jobs, in-process with the API (single Fly machine v1). Per-user fan-out at bounded concurrency. Guardian + dedupe make duplicate ticks idempotent.

Cron schedule (UTC)cloud/src/workers/scheduler.ts
CronJob nameHandlerWhat it does
0 12 * * *curator-tickrunCuratorTickFan-out to every user with sub or activity last 60d → CuratorAgent
0 */6 * * *concierge-sweep-tickrunConciergeSweepTick4×/day sweep of users with ≥1 WatchlistItem → ConciergeAgent
5 1 * * *tenant-usage-rollup-tickStripeMetersService.rollupCurrentPeriod()Forward (current − reported) deltas to Stripe Meters

Fan-out semantics

Concurrency 5 users in parallel per tick (a small Promise-pool worker pattern). Hard ceiling 1000 users/tick so a backlog after an outage can't fan into a million jobs. AgentRunner records failed runs — thrown errors never propagate, so one bad user can't kill the tick.

Idempotency by design

BullMQ scheduler IDs include the cron pattern (`curator:${CURATOR_CRON}`); a redeploy upserts, never duplicates. AgentEvent dedupeKey + 24h window suppress repeated emissions. Stripe Meters identifier is "<period>::<tenant>::<metric>::<count>" — a manual re-run of today's rollup is a no-op at the Stripe side.

PWA push + email digest

Two transports for AgentEvents beyond the in-app inbox. Both gated on env vars — missing keys downgrade to no-op without crashing.

VAPID web-push (P4.3)PushService.ts
  • One row per (user, endpoint) in PushSubscription. Endpoint is the unique key.
  • AgentEventStore.insert fires notifyUser after every successful insert. Fire-and-forget; failures isolated.
  • 410/404 from the provider auto-marks disabledAt — row stays for audit; UI shows "expired."
  • sw.js v2 uses tag=eventId + renotify=false so re-delivers don't buzz again.
  • Click reuses an open tab on origin instead of fanning a new tab per click.
Resend weekly digest (P4.4)EmailService.ts
  • Sunday 14:00 UTC tick walks users with digestEnabled=true & lastDigestAt outside the current week-bucket.
  • Pulls last 7 days of unseen events; sends HTML + text twin via Resend.
  • Never sends an empty digest. Bumps lastDigestAt only on success → re-tick is a no-op same week.
  • Settings UI's DigestSection reads transportConfigured — surfaces "not configured on this deploy" when RESEND_API_KEY is unset, instead of letting the toggle lie about behavior.

Billing & usage

Two Stripe surfaces: subscription billing for consumer tiers; usage-based metering for IaaS. Same Stripe customer model, different price paths.

Consumer subsStripeService.ts

FREE · default. PRO · STRIPE_PRO_PRICE_ID. PREMIUM · STRIPE_PREMIUM_PRICE_ID. Checkout via POST /billing/checkout; portal session for cancellation; webhook handler verifies STRIPE_WEBHOOK_SECRET + writes to BillingEvent.

IaaS usageStripeMetersService.ts

Per-tenant TenantUsage tracks signalsIngested / queriesServed / embeddingsBilled. Daily rollup (01:05 UTC) computes delta against per-metric watermark, posts to meter_events.create() with deterministic identifier <period>::<tenant>::<metric>::<count>. Reruns can't double-bill. Free-tier tenants without a Stripe customer ID are skipped wholesale.

Cost ceilings that are enforced in code
  • Per user, per day — $0.10 LLM cap (GuardianAgent). Hit it, agents return status='capped'.
  • Per CardScorer call — MAX_LLM_CALLS_PER_REQUEST = 10.
  • Per tenant, per month — plan quota; 429 with resetsAt = next-month-boundary.
  • Per worker tick — MAX_USERS_PER_TICK = 1000.
  • Per Keepa burst — server-reported token-bucket honored; 0 tokens → calls short-circuit to null.

Security & privacy posture

ADR-0010 is the canonical reference. Highlights of what's actually enforceable in CI or runtime today vs what's still on the checklist.

Enforced today
  • JWT with 15-minute access + 30-day refresh; refresh tokens hashed at rest.
  • API keys SHA-256 hashed; raw key shown once at issuance; prefix-only UI display.
  • Tenant isolation via composeTenantUserId; X-User-Id mismatch returns 403.
  • Watchlist deletion scoped by userId (deleteMany({where:{id,userId}})); forged IDs from other users can't mutate rows.
  • CORS allow-list with chrome-extension://* + configured origins.
  • Husky pre-commit blocks *.pem, creds*, dist.crx, dist/**, coverage/**, .env, .env.local on add/modify.
  • No LLM keys in extension; host_permissions trimmed to capture targets (P0.4).
  • GDPR delete idempotent across Postgres + Neo4j + Qdrant via forgetUser; DELETE /intelligence/me + DELETE /v1/users/:ext.
Open / on the checklist
  • P0.1 — dist.pem rotation + move to Fly secrets.
  • P0.2 — creds.txt → .env.example + gitignore.
  • P0.3 — untrack dist.crx, gitignore dist/.
  • JWT_ACCESS_SECRET + JWT_REFRESH_SECRET rotation after P0.1 (defense-in-depth).
  • VPC perimeter + per-tenant encryption keys (deferred, enterprise unlock).
