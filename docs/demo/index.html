01 · Why

The chat surface is not the product. The graph is.

A generic LLM front door competes against Perplexity, ChatGPT, and Google AI on a fight we cannot win. The one defensible asset is the user's own attention history — captured at the signal level — that no other AI provider can replicate from public web data.

Perplexity / ChatGPT

Searches the world

  • Source: the public web, fresh per query
  • Memory of you: none, or shallow text notes
  • Wins at: "what is X?"
  • Defensibility: search infra + brand (immense)
  • Action awareness: zero
Recome

Searches your past attention

  • Source: YOUR captures across every platform
  • Memory of you: structured graph + decay
  • Wins at: "what did I look at?"
  • Defensibility: your own data they can't re-create
  • Action awareness: knows what you almost bought
Questions only Recome answers
  • What was I researching last Tuesday?
  • I'm about to buy this — does it conflict with anything I learned earlier?
  • Summarize my standing-desks research across all platforms in the last 3 weeks.
  • Find the YouTube reviewer who said brand X has bad bearings.
  • I've been on the fence about X for too long — decide for me, here's what you saw me consider.
Perplexity literally cannot answer these. We can — once capture is dense.

02 · Architecture

One stack, two surfaces.

Consumer at recome.app and IaaS at /v1 share exactly one backend, one intelligence service, one set of data stores. The consumer product is just the first customer of the IaaS API — the same pattern as the Stripe dashboard calling the Stripe API.

Auth model

Two surfaces, two auth

Consumer uses JWT (15m access + 30d refresh, rotation, reuse-detection). IaaS uses rk_live_… / rk_test_… Bearer with SHA-256 hash storage and instant revocation.

Isolation

Multi-tenant by construction

Graph isolation via composed userId tenant_<tid>__<ext>. Vectors via per-tenant Qdrant collection. Cross-tenant queries impossible without an explicit reverse — and a unit test pins the invariant.

Production posture

Boring stack, novel product

Fly + Vercel + Neon + AuraDB + Qdrant Cloud. Every layer pickable on a managed tier. Self-host alternatives documented for each in case bills bind.

04 · Data model

What the graph remembers.

Six node labels. Nine typed relationships. Decay on every edge. The schema is small on purpose — most of the value comes from the volume of signal flowing through it, not from clever shapes.

Decay & strength — the math

Intent strength accumulates per signal and decays exponentially. τ defaults to 14 days; old topics fade, recent ones surface. The formula is small enough to hold in your head — that's deliberate. 

// brain/intelligence — intent strength
strength_t+1 = strength_t · decay + Δ
  decay = exp(-Δt / τ)        // τ = 14d default
  Δ     = kind_weight · user_action · source_trust

  kind_weight = {
    view:     1.0,
    dwell:    1.5,   // ≥10s
    like:     3.0,
    purchase: 5.0,
    block:    0,     // → state = blocked
  }
Edges

9 types

VIEWED, HAS_INTENT, BLOCKS, BOOSTS, MENTIONS, CONTAINS_ENTITY, RELATED_TO, SIMILAR_TO, CONTAINS

Nodes

6 labels

User, Topic, Entity, Page, Session, Signal

05 · Isolation

Two tenants. One backend. Zero crossings.

The IaaS surface multiplexes hundreds of customers onto one stack. Isolation lives at two layers: composed userId in the graph, dedicated collections in the vector store. A single helper (composeTenantUserId) is the only place a tenantId is ever encoded — and a test pins the invariant against the one regex bug that would leak across tenants.

Graph isolation

Composed userId

Every node and relationship carries a userId. IaaS users are tenant_<tid>__<ext>. Consumer users are bare CUIDs. Prefix is reserved — collision impossible.

Vector isolation

Per-tenant collections

One Qdrant collection per tenant. Cross-tenant queries cannot reach across collections — the boundary is the collection name, not a filter clause.

GDPR

One-call delete

DELETE /v1/users/:id drops Neo4j namespace + Qdrant points in one transaction. Right to Erasure honored in <72h end-to-end.

07 · Roadmap

Four phases. One falsifiable hypothesis each.

Each phase ends with a go / pivot / shelve review against measured KPIs. No phase carries forward without proof the last one worked. The kill criteria are real.

P0 · 6 weeks

Capture works

Paste + PWA + LLM extraction. Onboarding <90s. Migrations in.

Hypothesis: <5s capture from any device, no install.
Kill: <20% capture ≥10 items in week 1.
P1 · 8 weeks

Memory feels magical

Bulk import. Trail-of-the-week. Weekly digest. Decay tuning.

Hypothesis: week-2 retention ≥25%.
Kill: lower → re-examine extraction & ranking.
P2 · 10 weeks

Chat that wins

Real LLM agent · streaming · 6 tools · citations · side-by-side test vs Perplexity.

Hypothesis: ≥60% prefer Recome for personal-memory Qs.
Kill: >40% prefer Perplexity → pivot to bundling.
P3 · 12 weeks

IaaS lands

Self-serve · docs site · JS+Python SDKs · Stripe metered · gRPC + webhooks.

Hypothesis: 10 paying tenants in 12 weeks.
Kill: <5 → reposition or shelve.

09 · IaaS

The same backend, exposed as a public contract.

Recome's own web app is the first customer of /v1. There is no second backend. Stripe uses this pattern — their dashboard calls their public API. So do we.

Public endpoints (live)

POST /v1/signals ingest

Batched signal ingestion. Idempotent on signal.id. Quota-checked.

GET /v1/users/:id/trails query

Cross-platform research trails for one of the caller's end-users.

GET /v1/users/:id/trails/:topic query

Single trail with related-topic suggestions + strength explanation.

GET /v1/users/:id/intents query

Top intents ranked by recency × volume × cross-platform count.

DELETE /v1/users/:id erase

GDPR-compliant single-call delete. Drops Neo4j namespace + Qdrant collection.

GET /v1/usage meta

Current-period counters + quota + reset timestamp.

Hello world — <50 LOC

// JS — npm i @recome/intelligence
import { Recome } from '@recome/intelligence';

const client = new Recome({
  apiKey: process.env.RECOME_KEY,   // rk_live_…
  userId: 'user_42',                // your end-user
});

// 1. Ingest a signal
await client.signals.ingest({
  kind: 'view',
  pageUrl: 'https://reddit.com/r/buyitforlife/…',
  topics: [{ name: 'standing desks' }],
});

// 2. Read back the trail
const trail = await client.trails.get('standing desks');
console.log(trail.platforms, trail.strength);
// → ['youtube', 'reddit', 'amazon'], 0.78
