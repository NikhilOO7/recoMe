01 — The Problem

Why RecoMe Exists

Modern social media and shopping feeds are optimised for engagement, not for your wellbeing or goals. Users scroll through irrelevant ads, creators they've long lost interest in, and content that contradicts their current focus. Existing blockers are dumb — they block keywords or domains globally with no concept of context, relevance, or time.

🎯

Contextual Blindness

Blocking "crypto" while at work should not block it when you're doing personal research. Context matters — no current tool understands this.

🧠

No Memory

Feedback given to an algorithm is forgotten or misapplied. You hide a video today but it comes back tomorrow under a different creator.

🔗

Semantic Gap

Blocking "Bitcoin" doesn't block "BTC" or the creator who makes Bitcoin videos. No relationship understanding exists in today's tools.

💡

RecoMe's Answer: A browser extension that builds a personal model of your interests using a Smriti memory system and a knowledge graph — so it understands not just what you want hidden, but why, when, and for how long.

03 — Layer Deep Dives

Each Layer Explained

🪟

UI Layer — Presentation

React 18 · Content Scripts · Popup

What: Every pixel the user sees. Divided into two parts — platform-specific content scripts that run in the page and inject overlay UI, and the extension popup (React app) for global settings and dashboards.

Why separate: Content scripts must be lightweight (they run in every page load) while the popup can be a full React SPA. Platform adapters know page DOM structure; the popup knows user intent.

Platform Adapter

Observes DOM mutations via MutationObserver, extracts content metadata, sends to background, injects hide/show overlays with animations.

Feedback Controls

Thumbs-up/down, hide buttons rendered on each content card. Capture user feedback and dispatch FEEDBACK messages to background.

React Popup

Dashboard showing memory stats, blocked topics, graph visualisation, context switcher, settings sliders for aggressiveness.

⚙️

Background Service — Orchestration

Service Worker · MV3 · Message Broker · Event Bus

What: The central nervous system. A Manifest V3 service worker that lives as long as there are open connections or alarms. Receives all messages from content scripts and popup, routes them to the right intelligence service, and sends back scored recommendations.

Why a service worker: MV3 requires service workers instead of background pages. They are event-driven, ephemeral — they wake up to handle events and can be terminated by Chrome. All state must be persisted to IndexedDB rather than in-memory globals.

Message Broker

Routes typed messages between content scripts, popup, and internal services. Validates message schemas. Returns typed responses. Acts as the single communication gateway.

Event Bus (Pub/Sub)

Internal event system for decoupling services. MemoryService publishes PATTERN_DETECTED; RecommendationEngine subscribes. No tight coupling between intelligence services.

Decay Manager

Runs on a chrome.alarms schedule (every 15 minutes). Walks through all memory entries and transitions them through the forgetting lifecycle: Core → Dream → Forgotten → Deleted.

Alarm Manager

Wraps chrome.alarms API to schedule periodic housekeeping: decay runs, cache invalidation, graph pruning, and statistics aggregation.

🧠

Intelligence Layer — Domain

MemoryService · KnowledgeGraph · RecommendationEngine · ContextDetector

What: The brain of RecoMe. Three co-operating systems that together produce intelligent, context-aware, time-aware content filtering decisions. All pure business logic — no DOM access, no Chrome APIs, fully unit-testable.

Why separated: Each system has a distinct responsibility and a different rate of change. The memory system changes on every user interaction. The knowledge graph changes when feedback implies new semantic relationships. The recommendation engine just reads from both and scores.

💾

Data Layer — Infrastructure

IndexedDB · chrome.storage · LRU Cache · Repository Pattern

What: Handles all persistence. Uses IndexedDB via a typed repository abstraction (not raw IDB calls). Intelligence services never talk to IndexedDB directly — they go through repositories, which makes testing trivial and storage backends swappable.

Why IndexedDB: The only browser-side storage capable of storing structured, indexed, multi-GB data. localStorage would be too slow and size-limited for the memory system. chrome.storage.local has a 10MB cap. IndexedDB has no practical limit and supports efficient range queries.

04 — Smriti Memory System

Human-Like Memory

Named after the Greek goddess of memory and mother of the Muses, Smriti is the most novel part of RecoMe. It models memory the way humans remember things — not as a flat list of rules, but as contextual, time-decaying impressions that fade naturally when not reinforced.

Context Buckets

Every memory entry is tagged with a context. The context is detected automatically from time of day, active tab URL, and content type. A "hide crypto" preference in Work context does not apply in Learning context.

💼

Work

Weekdays 9am–6pm. Deep focus. High content filtering aggressiveness.

📚

Learning

Detected from educational domains, tutorial sites, documentation.

🛒

Shopping

Amazon, eBay, Walmart active tabs. Product comparison mode.

🎮

Entertainment

Evening hours, YouTube, social platforms. Relaxed filtering.

👥

Social

Twitter, Facebook active. Community-focused content signals.

🌐

General

Fallback when context is ambiguous. Uses moderate defaults.

Memory Lanes Architecture

Memory is not one flat store — it has lanes that mirror human cognitive architecture: working memory, short-term, mid-term patterns, and long-term preferences.

⚡ Short-Term

Ring buffer · Last 50 interactions · TTL 2h

Hid "Crypto" video — YouTube
Liked "React" tutorial — Twitter
Skipped "Ad" post — Facebook

Newest evicts oldest. Used for immediate context.

🃏 Mid-Term Patterns

Pattern cards · Threshold 5+ events · TTL 30d

Block pattern: Crypto content
Interest pattern: React/TypeScript
Research pattern: AI tools

Auto-formed when short-term events cluster.

🎯 Working Set

Hot cache · Current session · In-memory

Ephemeral. Drives instant scoring decisions.

📜 Long-Term

Always show: Tech news

Explicit user rules. Never auto-deleted.

Decay Policy: Short-term entries decay in 2h. Mid-term patterns survive 30d. Long-term preferences never decay unless explicitly deleted. Timings are configurable per-user.

🔄

Reinforcement: Every time a memory entry is accessed (not just written), its lastAccessedAt updates and it stays CORE. Frequently-used memories never fade.

Pattern Detection

Short-term events are continuously monitored by the PatternDetector. When ≥5 events of the same type cluster around the same topic, a mid-term pattern card is automatically created.

Block Pattern

5+ hide/dislike events for same topic → auto-block rule created

Interest Pattern

5+ engage/like events for topic → boost rule + graph affinity update

Research Pattern

Repeated visits to a topic over time → temporary interest spike, not permanent

Time Pattern

Consistent behaviour at specific hours → context-aware scheduling

Context Pattern

Preferences differ by context → separate rules per context bucket

Cross-Platform

Same topic hidden on both YouTube and Twitter → global rule elevated in strength

07 — Platform Adapters

Multi-Platform Support

Each platform has a dedicated content script adapter. Adapters follow the BaseAdapter interface but implement platform-specific DOM selectors, metadata extractors, and injection points.

📺

YouTube

Video cards in feed, search results, recommended sidebar. Extracts title, channel, duration, views, thumbnail. Observes feed scroll with MutationObserver.

🛒

Amazon

Product listing cards in search results and recommendations. Extracts product name, brand, ASIN, price, rating. Filters sponsored vs organic.

𝕏

Twitter / X

Timeline tweets, promoted content, "You might like" section. Extracts author, hashtags, entities, engagement counts. Handles both old and new X UI.

📘

Facebook

News feed posts, suggested pages, sponsored posts. Extracts page name, post type, topics. Handles both desktop and mobile-web layouts.

🏷️

eBay

Search results, category listings, sponsored items. Extracts item title, seller, price, condition. Used for shopping context filtering.

🏪

Walmart

Product search and category pages. Extracts product info, brand, department. Works alongside Amazon for cross-platform shopping preferences.

Base Adapter Interface

interface BaseAdapter {
  platform: Platform;                          // 'youtube' | 'amazon' | 'twitter' | ...

LRU Cache Layer

Frequently-accessed data (like affinity scores for common topics) is kept in an in-memory LRU cache to avoid redundant IndexedDB reads on every content card scored.

Affinity Cache

LRU(500 entries), TTL 5min. Stores pre-computed affinity scores for entity pairs. Invalidated on graph updates.

Memory Cache

LRU(200 entries), TTL 2min. Caches recent memory lookups. Invalidated on new writes to MemoryStore.

Pattern Cache

LRU(100 entries), TTL 10min. Caches active pattern cards. Invalidated when PatternDetector creates new patterns.

09 — Message Protocol

Communication Layer

All cross-context communication (content script ↔ background ↔ popup) uses Chrome's runtime.sendMessage with a strictly-typed message protocol. Every message has a discriminated union type for full TypeScript narrowing.

Content Script → Background

SCORE_CONTENT Request scoring for a detected content card. Payload: ContentMetadata. Response: { score, action: 'hide'|'show'|'boost' }
RECORD_FEEDBACK User clicked thumbs up/down or hide. Payload: { contentId, type: FeedbackType, context }. Triggers memory write + graph update.
CONTENT_VISIBLE Content scrolled into view. Triggers implicit tracking for engagement patterns. Payload: { contentId, duration? }
GET_CONTEXT Ask background what context the user is in right now. Response: { context: ContextType }. Used by adapters before rendering UI.

Background → Content Script

APPLY_DECISION Push a scoring decision to the content script. Payload: { contentId, action, score }. Used for async re-scoring after pattern detection.
CONTEXT_CHANGED Broadcast when context switches (e.g. work→entertainment). All adapters re-score visible content with new context weights.

Popup → Background

GET_STATS Request aggregated statistics for the dashboard. Response: { hiddenToday, patternsActive, memoryCount, topBlockedTopics }
UPDATE_SETTINGS User changed aggressiveness slider or toggled a platform. Triggers re-scoring and cache invalidation.
CLEAR_MEMORY User explicitly clears all memory. Triggers full IndexedDB wipe and graph reset to seed data only.
EXPORT_DATA Export all user data as JSON. Privacy feature — lets users inspect or backup their memory and graph data.
10 — UI & UX Design

Design System & Interaction

RecoMe is built on the principle that the UI should feel invisible — it acts quietly and only surfaces itself when meaningful. Interactions are delightful but never interruptive.

Design Principles

Invisible by Default

Filtering happens silently. The user's feed just gets better — no popups, no notifications, no friction.

Delight in the Details

When content is hidden, it fades out with a gentle animation. When revealed, it slides back in smoothly. Every micro-interaction is considered.

Always Reversible

Anything hidden can be revealed. Preferences can be cleared. The user is always in control — RecoMe is a tool, not an authority.

Transparent Reasoning

Hovering over a hidden card shows exactly why it was hidden: "Hidden because: Crypto (Work context, 87% confidence)".

11 — Tech Stack

Technology Choices

Core Technologies

TypeScript 5
Full type safety across all layers. Discriminated unions for message types. Generics for repository pattern.
React 18
Popup UI only. Concurrent mode for smooth animations. React DevTools for debugging popup state.
Webpack 5
Multi-entry build (background, popup, each content script). Tree-shaking and code splitting. Source maps for debugging.
Jest + Testing Library
Unit tests for all intelligence services. IDB mock for storage tests. Coverage targeting 80%+.
IndexedDB (idb library)
Jake Archibald's idb wrapper. Promise-based API over raw IndexedDB. Version migration support built-in.

Chrome Extension APIs Used

chrome.runtime
sendMessage, onMessage, onInstalled. Core communication backbone.
chrome.storage.sync
User settings only. Syncs across devices. 100KB limit — settings are tiny.
chrome.alarms
Schedule decay runs every 15min. Persist through browser restarts unlike setTimeout.
chrome.tabs
Active tab detection for context inference. Read-only tab metadata only.
MutationObserver API
Watch for new content cards injected into the feed DOM. More efficient than polling.

Architecture Principles

Separation of Concerns

UI knows nothing about scoring. Intelligence knows nothing about DOM. Data knows nothing about Chrome APIs. Clean boundaries enforced by TypeScript interfaces.

Dependency Injection

Services receive their dependencies via constructors. No module-level singletons. Makes unit testing trivial — inject mocks.

Fail Gracefully

IndexedDB errors should never crash content scripts. Circuit-breaker pattern: after 3 failures, return neutral score and log error. User experience is never broken.

Privacy by Default

No network requests. No analytics. No telemetry. All data is user-owned and user-deletable. GDPR-compliant by architecture, not policy.

13 — Key Design Decisions

Architecture Decision Log

Why Manifest V3 (not V2)?

Google deprecated MV2. All new extensions and updates to existing ones must target MV3. While service workers are more complex than persistent background pages, they are the only supported option. We accept the complexity and design around the ephemeral service worker model by ensuring all state is persisted to IndexedDB before the worker sleeps.

Decision

Why IndexedDB over chrome.storage.local?

chrome.storage.local has a 10MB quota (by default 5MB without unlimitedStorage permission). A user who browses for a year could easily have thousands of memory entries and thousands of graph nodes. IndexedDB has no practical size limit and crucially supports compound indexes — essential for efficient context-filtered queries like "all CORE memories in WORK context sorted by lastAccessedAt".

Decision

Why content scripts over a page-level SDK?

Content scripts run in isolated contexts, cannot be blocked by the page's CSP, and do not pollute the page's JavaScript namespace. A page-level script would require website cooperation (impossible for third-party filtering) and could be blocked. Content scripts with MutationObserver are the only reliable way to monitor and modify live feed content.

Decision

Why local-only? No cloud sync?

User browsing preferences and content interaction data is deeply personal. Sending it to a server — even encrypted — creates a privacy risk, requires user authentication, backend infrastructure, and ongoing maintenance costs. Local-only means zero operating costs, zero data breach risk, and a simple privacy story. A future encrypted cloud sync (E2E, zero-knowledge) is planned but intentionally deferred.

Future

Why a knowledge graph instead of just keyword lists?

"Bitcoin" and "BTC" are the same thing. A crypto creator's channel is related to crypto. If you dislike crypto you probably dislike NFTs. None of this semantic understanding is possible with keyword lists. The graph lets affinity propagate through semantic relationships, catching content that would slip through keyword filters while avoiding false positives (a "blockchain" article in a cybersecurity context is different from a "blockchain" crypto promotion).
