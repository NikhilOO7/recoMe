## 2. `intelligence/` — the capture/retrieve service layer

**Files:** [cloud/src/intelligence/](../../cloud/src/intelligence/)
**Owns:** the one and only entry point for signal ingestion and graph read.

### 2.1 `IntelligenceService`

[File: cloud/src/intelligence/IntelligenceService.ts](../../cloud/src/intelligence/IntelligenceService.ts)

```ts
class IntelligenceService {
  readonly graph: GraphRepository;
  readonly ingestion: SignalIngestion;
  readonly trails: ResearchTrailService;
  readonly neo4j: Neo4jClient; // exposed for agents that need raw cypher
  readonly vectors: VectorClient;
  readonly embedder: EmbeddingClient;

  constructor(neo4j, vectors, embedder, opts);
  async start(): void; // awaits deps, runs cypher migrations if opt-in
  async health(): { ok; neo4j; qdrant }; // /ready endpoint reads this
  async forgetUser(userId): { nodesDeleted; relsDeleted; vectorsDeleted };
}

// Singleton accessors used everywhere:
function setIntelligence(svc): void;
function getIntelligence(): IntelligenceService; // throws if unset
function maybeIntelligence(): IntelligenceService | null;
```

**Lifecycle:** constructed once in `bootstrap.ts#bootIntelligence()` only when `INTELLIGENCE_ENABLED=true`. `start()` awaits Neo4j + Qdrant ready, optionally runs migrations. Throws hard-fail at boot if a required env var is missing — operator sees misconfig at deploy, not first request.

**Why the singleton pattern over DI container:** ergonomic for the size of the codebase (~30 modules); explicit at call site (`getIntelligence().graph.…`); easy to mock in tests by setting a fake. No magic injection.

### 2.2 `SignalIngestion`

[File: cloud/src/intelligence/SignalIngestion.ts](../../cloud/src/intelligence/SignalIngestion.ts)

```ts
interface SignalInput {
  id?: string; // client-generated, idempotency
  userId: string; // raw cuid (consumer) or tenant_x__y (IaaS)
  kind: SignalKind; // view | dwell | like | block | boost | purchase | comparison | search
  ts?: number; // unix ms
  weight?: number; // 0..100, defaults from kind
  pageUrl?: string;
  pageTitle?: string;
  platform?: Platform; // youtube | reddit | amazon | ...
  topics?: Array<{ name: string }>;
  entities?: Array<{ name; kind; platform? }>;
  sessionId?: string;
  metadata?: Record<string, string | number | boolean>;
}

interface IngestResult {
  signalId: string;
  topicsCreated: number; // newly inserted topics
  entitiesCreated: number;
  embeddingsGenerated: number;
}

class SignalIngestion {
  async ingest(input: SignalInput): Promise<IngestResult>;
}
```

**Pipeline order** (load-bearing — see [HLD §3.1](0015-hld.md#31-capture-flow-extensionpastepwaiaas--graph)):

1. Normalize topics (`normalizeTopic()` lowercases, strips punctuation, dedupes by normalized name within request).
2. Upsert Page if `pageUrl` + `platform` present.
3. Upsert Topics + Entities (Neo4j MERGE, idempotent on natural key).
4. Embed topics + entities (OpenAI, on critical path today; planned to move to BullMQ).
5. Upsert vector points to Qdrant in user's namespace.
6. `recordSignal` — single Cypher UNWIND that creates the Signal node and all relationships (MENTIONS, HAS_INTENT EWMA, BLOCKS/BOOSTS).
7. **Fire event-triggered agents** — `fireSignalIngestTriggerSync()` (fire-and-forget per topic).

**Error semantics:**

- Validation failure → caller responsibility (Zod parse before calling `ingest`).
- Neo4j write failure → propagates, request returns 500. Idempotency: re-running the same `id` is safe via MERGE.
- Embedding failure → logged warn, ingest continues without vectors (graph is source of truth, vectors are accelerators per ADR-0001).
- Agent trigger failure → swallowed (agents are best-effort; one bad agent can't poison ingest response).

### 3.2 `types.ts` — the contract

```ts
type AgentTrigger = 'scheduled' | 'event' | 'on_demand';
type AgentRunStatus = 'started' | 'succeeded' | 'skipped' | 'capped' | 'failed';
type AgentEventKind =
  | 'recall'
  | 'deal_drop'
  | 'new_alternative'
  | 'fresh_content'
  | 'decision_nudge'
  | 'weekly_summary';

interface AgentEventSource {
  kind: 'signal' | 'topic' | 'page' | 'entity';
  id: string;
  label?: string;
  url?: string;
}

interface AgentEmission {
  kind: AgentEventKind;
  title: string;
  body?: string;
  actionUrl?: string;
  sources: AgentEventSource[]; // MANDATORY per ADR-0012 §5
  dedupeKey: string; // `<agent>:<topic-or-entity>:<bucket>`
}

interface AgentContext {
  userId: string;
  trigger: AgentTrigger;
  event?: Record<string, unknown>; // trigger-specific payload
  now: Date; // pass through; never Date.now() inside agents
}

type AgentResult =
  | { status: 'succeeded'; emit: AgentEmission; llmTokens?; costMicros? }
  | { status: 'skipped'; reason: string; llmTokens?; costMicros? }
  | { status: 'failed'; error: string };

type GuardianDecision = { allow: true } | { allow: false; status: 'capped'; reason: string };
```

These types are dependency-free (no Prisma import) so they're safe to use in tests and triggers without dragging the world.

### 3.3 `BaseAgent` + concrete agents

```ts
abstract class BaseAgent {
  abstract readonly name: string;
  abstract readonly displayName: string;
  abstract readonly triggers: ReadonlyArray<AgentTrigger>;
  async canRun(ctx: AgentContext): Promise<boolean> {
    return true;
  }
  abstract run(ctx: AgentContext): Promise<AgentResult>;
}
```

To add a new agent (Concierge, Curator, etc.):

1. Subclass `BaseAgent`. Set `name`, `displayName`, `triggers`.
2. Override `canRun` if there's a cheap pre-check.
3. Implement `run`. Return `AgentEmission` with mandatory `sources` array.
4. Register in `agents/index.ts#bootAgents()`.
5. Add throttle constant to `GuardianAgent.AGENT_MIN_GAP_HOURS` if applicable.
6. Add unit tests for scoring / decision logic in `__tests__/`.

### 3.4 `AgentRunner` — the lifecycle chokepoint

[File: cloud/src/agents/AgentRunner.ts](../../cloud/src/agents/AgentRunner.ts)

The single function `runOne(agent, ctx)` is the entire agent execution surface. Sequenced:

```
runOne(agent, ctx)
  ├─ try { canRun = await agent.canRun(ctx) }
  │  catch → canRun = false (swallowed warn)
  ├─ if !canRun: return 'skipped'    (no AgentRun recorded)
  │
  ├─ guardian.check(agent.name, ctx)
  │  ├─ if !allow: persist AgentRun(status='capped', meta.reason) → return 'capped'
  │
  ├─ try { result = await agent.run(ctx) }
  │  catch → persist AgentRun(status='failed', meta.error) → return 'failed'
  │
  ├─ on result.status === 'failed': persist AgentRun → return 'failed'
  ├─ on result.status === 'skipped': persist AgentRun → return 'skipped'
  ├─ on result.status === 'succeeded':
  │    ├─ eventId = AgentEventStore.insert(userId, agent.name, result.emit)
  │    │           (returns null if dedupe-suppressed)
  │    ├─ if eventId: guardian.recordEmission(userId, agent.name, finishedAt)
  │    └─ persist AgentRun(status='succeeded', meta={eventId, suppressed: !eventId})
```

**Invariants:**

- An agent never throws to the caller — failures are recorded.
- One bad agent can't poison siblings in `Promise.allSettled` from the trigger.
- Every invocation writes an `AgentRun` row — the audit trail is complete.
- Dedupe-suppressed emissions still write `AgentRun` (status='succeeded', meta.suppressed=true) so the user-facing audit log shows "Recall ran on this signal but suppressed because already shown this week."

### 3.5 `GuardianAgent` — binding constraints

[File: cloud/src/agents/GuardianAgent.ts](../../cloud/src/agents/GuardianAgent.ts)

Four checks per `check()` call, short-circuiting on the first deny:

1. **Subscription / pause** — `AgentSubscription.enabled === false` or `pausedAt != null` → deny (except `on_demand`).
2. **Per-agent throttle** — `AGENT_MIN_GAP_HOURS[name]` vs `lastEmittedAt`. Currently `recall: 84h` (≈2/wk).
3. **Daily cost cap** — sum `AgentRun.costMicros` in last 24h vs `dailyCostCapMicros` (default $0.10 = 100_000 micros).
4. **Quiet hours** — `22:00–08:00` UTC v1; per-tz pending honest gap (see [HLD §10 open #2-equivalent for tz](0015-hld.md#10-open-architectural-decisions)).

Returns `GuardianDecision`. Never throws.

**Tunable knobs** (all defaults, overridable per `AgentSubscription.config`):

- `dailyCostCapMicros: 100_000` ($0.10/day; Plus tier raises to $1M = $1; Pro unlimited)
- `quietHoursStart: 22`, `quietHoursEnd: 8`

Adding a new agent's throttle: edit `AGENT_MIN_GAP_HOURS` constant. No code generation, no config DB.

### 3.6 `AgentEventStore` — inbox dedupe

[File: cloud/src/agents/AgentEventStore.ts](../../cloud/src/agents/AgentEventStore.ts)

```ts
class AgentEventStore {
  async insert(userId, agent, emit, dedupeWindowMs = 24h): Promise<string | null>
  // Returns event ID on insert, null if a row with same (userId, dedupeKey)
  // exists within the window.

  async listForUser(userId, { limit, since, onlyUnseen }): AgentEvent[]
  async markSeen(userId, eventId): void
  async recordFeedback(userId, eventId, 'useful' | 'not_useful'): void
}
```

**Tenant safety:** every update uses `updateMany({ where: { id, userId } })` so a forged eventId from another user can never be flipped. The `where.userId` clause is the isolation guarantee at this layer (the composeTenantUserId pattern handles it at the graph layer).

**Dedupe window choice:** 24h default. Each agent picks its own `dedupeKey` shape:

- Recall: `recall:<topicNormalized>:<weekBucket>` — at most one per topic per week.
- Concierge (planned): `concierge:price-drop:<entityId>:<dayBucket>:<pricePercentile>` — at most one price-drop alert per entity per day per price tier.

### 3.7 `RecallAgent`

[File: cloud/src/agents/recall/RecallAgent.ts](../../cloud/src/agents/recall/RecallAgent.ts)

**Algorithm:**

1. Trigger payload: `{ signalId, topicNormalizedName, topicName, ts }` from `SignalIngestion`.
2. `canRun` validates the payload shape.
3. Cypher query: signals on same topic, ts < (now − 14d), excluding trigger. Returns top 5 by ts DESC.
4. `pickBest` scores each candidate: `weight × ageFactor`, where ageFactor is a triangle that peaks at 21d and decays past 60d. Returns the highest-scoring signal.
5. If score < 0.4 → `skipped`.
6. Build `AgentEmission` with:
   - title: templated `"You looked at this N days ago — still relevant"` (LLM polish is follow-on within $0.05/user/mo budget)
   - sources: forgotten signal + trigger signal + topic
   - dedupeKey: `recall:<topicNormalized>:<weekBucket>`
7. Zero LLM tokens v1. Deterministic ranking only.

**Test coverage** ([**tests**/RecallAgent.test.ts](../../cloud/src/agents/__tests__/RecallAgent.test.ts)):

- Age peak (25d beats 14d, both weight 1)
- Old-signal decay (21d weight 1 beats 200d weight 5 — important property)
- Weight tiebreak when ages match
- Score threshold above 0.9 at peak (provides ceiling for confidence)
- `canRun` rejects malformed events

## 5. `graph/` — Neo4j adapter

**Files:** [cloud/src/graph/](../../cloud/src/graph/)

### 5.1 `Neo4jClient`

[File: cloud/src/graph/Neo4jClient.ts](../../cloud/src/graph/Neo4jClient.ts)

```ts
class Neo4jClient {
  async ready(): void; // awaits driver
  async health(): { ok; latencyMs; error? };
  async read<T>(work, label?): Promise<T>; // executeRead session w/ retry
  async write<T>(work, label?): Promise<T>; // executeWrite session w/ retry
  async run<R>(cypher, params, label?): QueryResult<R>; // one-shot autocommit
  async close(): void; // for graceful shutdown
}
```

`read()` / `write()` use Neo4j's `executeRead` / `executeWrite` which handle bookmark-based causal consistency and transparent retry on transient errors. `run()` is a convenience for one-shot autocommit queries (used by RecallAgent's `queryForgotten`).

### 5.2 `GraphRepository`

[File: cloud/src/graph/GraphRepository.ts](../../cloud/src/graph/GraphRepository.ts)

Typed high-level surface. Avoid raw Cypher in service code — use these methods.

```ts
class GraphRepository {
  // Upserts (idempotent on natural keys)
  async upsertUser(user: UserNode): void;
  async upsertTopics(topics: TopicNode[]): void;
  async upsertEntities(entities: EntityNode[]): void;
  async upsertPage(page: PageNode): void;

  // Writes
  async recordSignal(signal: SignalRecord): void;

  // Reads
  async getResearchTrail(userId, topic): Trail | null;
  async getCrossPlatformTopics(userId, { minPlatforms, limit }): Trail[];
  async getTopIntents(userId, limit): Intent[];

  // GDPR
  async deleteUserData(userId): { nodesDeleted; relsDeleted };
}
```

When a query is single-use (RecallAgent's `queryForgotten`), the agent runs raw Cypher via `neo4j.run()`. When a second agent needs the same query, **promote to GraphRepository**. Avoids "every agent has its own bespoke Cypher" sprawl.

## 10. Error model — cross-cutting

Every error returned to a client follows the same shape:

```json
{ "error": "snake_case_code", "message": "...", "details": { ... } }
```

| HTTP code | When                      | Example                                                             |
| --------- | ------------------------- | ------------------------------------------------------------------- |
| 400       | client validation fail    | `{ error: 'invalid_signals', details: zodErrors }`                  |
| 401       | missing / invalid auth    | `{ error: 'invalid_key' }`                                          |
| 403       | user mismatch / forbidden | `{ error: 'user_mismatch' }`                                        |
| 404       | resource missing          | `{ error: 'trail_not_found' }`                                      |
| 415       | unsupported content type  | `{ error: 'not_html' }`                                             |
| 429       | quota / rate limit        | `{ error: 'quota_exceeded', resetsAt: '2026-06-01T00:00:00Z' }`     |
| 500       | server error              | `{ error: 'Internal server error' }` (details logged, not returned) |
| 502       | upstream failure          | `{ error: 'remote_error', status: 503 }`                            |
| 503       | dependency unhealthy      | `/ready` returns 503 when Neo4j/Qdrant probe fails                  |

The global error handler in `cloud/src/index.ts#app.onError` catches unhandled rejections, logs with full context (path, request id) into Sentry, returns generic 500 to client.

**Never return internal error details to the client.** The server log has them; the client doesn't need them. Mistakes here become information-disclosure CVEs.

## 13. Performance characteristics

What we know today, in honest numbers and where they come from.

| Operation                                | p50    | p95    | Source                                                |
| ---------------------------------------- | ------ | ------ | ----------------------------------------------------- |
| Capture (text-only signal, no embed)     | ~40ms  | ~80ms  | Local dev measurements                                |
| Capture (with OpenAI embed, 1 topic)     | ~210ms | ~380ms | Local dev + OpenAI latency observation                |
| Capture (batch of 10 signals, 10 embeds) | ~300ms | ~520ms | Local; would benefit from concurrent embed calls (P2) |
| Trail fetch (cold Neo4j)                 | ~30ms  | ~70ms  | Single MATCH on indexed userId+topic                  |
| Trail fetch (warm Neo4j cache)           | ~8ms   | ~20ms  | Same                                                  |
| Recall agent end-to-end (no LLM)         | ~25ms  | ~60ms  | Cypher + scoring, no I/O after query                  |
| Inbox list (30 events)                   | ~12ms  | ~30ms  | Postgres indexed scan                                 |
| Mind Map graph projection (planned)      | TBD    | TBD    | Need to benchmark Louvain on real user graphs         |
| Stripe webhook dispatch                  | ~50ms  | ~120ms | Includes signature verify + DB write                  |

**Known performance gaps:**

- OpenAI embed on critical capture path (220ms median). Move to BullMQ worker P2.
- Per-topic agent trigger fan-out is sequential within `Promise.allSettled`. Single agent today (Recall). When ≥3 agents, parallelism characteristics worth re-checking.
- Trail fetch's optional semantic-neighbors pass via Qdrant adds 60-150ms when enabled. Default off for v1.

## 14. How to extend the system (recipes)

Cookbook for the most common changes.

### 14.1 Add a new signal type

1. Add to `signalKindEnum` in [intelligence/schemas.ts](../../cloud/src/intelligence/schemas.ts).
2. Update `defaultWeight()` in [SignalIngestion.ts](../../cloud/src/intelligence/SignalIngestion.ts).
3. Update `isIntentSignal()` if it should drive HAS_INTENT.
4. Add to docs/0009 §3 if it implies new relationship semantics.

### 14.2 Add a new agent

See [§3.3 above](#33-baseagent--concrete-agents). Five steps; no runtime changes.

### 14.3 Add a new IaaS endpoint

1. Add route to [V1Controller.ts](../../cloud/src/iaas/V1Controller.ts).
2. Use `composeTenantUserId(tenantId, externalUserId)` — never the raw header.
3. `bumpUsage(tenantId, 'queriesServed', 1)` after success.
4. Add OpenAPI spec entry (P3 task).
5. Document on `docs.recome.app` (P3 task).

### 14.4 Add a new Prisma model

1. Edit `cloud/prisma/schema.prisma`.
2. `npx prisma migrate dev --name describe_change` (NOT `db push` — see [HLD §10 open #7](0015-hld.md#10-open-architectural-decisions)).
3. `npx prisma generate`.
4. Verify in test suite before commit.

### 14.5 Add a new third-party API dependency

1. New ADR (`0017-…`, etc.) explaining vendor choice + alternatives considered.
2. Add abstraction in `cloud/src/<area>/` (interface + concrete impl, like `EmbeddingClient` / `OpenAIEmbeddings`).
3. Configure via Zod env in `config.ts`.
4. Wire in `bootstrap.ts`.
5. Add cost line to [0011](0011-cost-and-iaas-gtm.md) cost model.
6. Document in [0005 tech stack](0005-tech-stack.md) §1.
