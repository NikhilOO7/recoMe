Why Pancreatic Cancer Reports Are Uniquely Hard

PDAC (Pancreatic Ductal Adenocarcinoma) reports arrive dense, multi-domain, and emotionally loaded. A plain LLM summary treats every patient — and every finding — identically.

📄

Reports are multi-domain

A single follow-up report combines CT imaging, tumor markers (CA 19-9), liver function, treatment response, staging, and surgical resectability — all with equal visual weight.

🔄

Context resets every visit

Without memory across sessions, every simplification starts from scratch. Patients re-learn what CA 19-9 means on every visit. What changed since last time goes undetected.

🎯

All findings treated equally

A new hepatic lesion (urgent) and stable fat stranding (background noise) get the same explanation weight. Patients don't know what to call their doctor about.

👤

No patient model exists

The LLM doesn't know this patient is on FOLFIRINOX cycle 4, asked about CA 19-9 three times before, or that their caregiver is the one reading the report.

2RecoMe SDK Components in Play

Four backend modules work together to build the personalization layer Pantory needs.

🧠

Interest Graph

A persistent knowledge graph of the patient's conditions, medications, interests, and confusion points — stored as weighted typed edges. Grows with every session.

entities + relations weighted edges
⚖️

OpportunityRanker

Scores each report finding using 4 signals: interest match, benefit clarity, timeliness, and novelty. Returns a ranked list — most important first.

4-signal scoring threshold filter
🗂️

Memory Pack

Short and mid-term memory cards per patient — tracks what terms were explained, what they re-read, and what comprehension gaps remain across sessions.

topic buckets cross-session
🔍

Profile Extractor

Parses structured data out of report text using registerable specialty modules — oncology, cardiology, labs — each knowing the report structure for that domain.

specialty modules structured output

Cold Start · James's First Upload

Building James's Medical Profile from Scratch

James uploads his first CT report and blood work. There is no prior context. The SDK's Profile Extractor parses the report using an oncology specialty module, extracting structured findings: tumor location (head of pancreas, 4.2 cm), CA 19-9 at 2,847 U/mL, SMV abutment, no hepatic metastases.

The Interest Graph is initialized with these entities and their relationships to James. The Memory Pack is created empty — no prior explanations yet.

💡

Why this matters vs. plain LLM

An LLM just summarizes text. The SDK builds a model of James — his conditions, their weights, what's clinically relevant to him. Every future session benefits from this foundation.

Cycle 2 Report · 6 Weeks Later

Context-Aware Extraction on the Second Upload

James uploads his cycle 2 CT + labs. This time the SDK loads his existing graph before doing anything. CA 19-9 is now 1,240 U/mL (down from 2,847). Tumor is 3.8 cm. Bilirubin slightly elevated.

The Interest Graph already knows James's conditions and the Memory Pack knows that CA 19-9 was explained to him last session. The extractor now outputs not just raw findings but delta signals — what changed, in which direction, by how much.

🔄

Delta detection in action

CA 19-9 dropped 56%. The graph records this trajectory. The ranker will later use this as a strong "timeliness" and "interest match" signal — James has shown he cares about this marker, and it has meaningfully changed.

Continuous Learning · Graph Updates

Every Interaction Improves the Next Report

After James reads his results, his behavior feeds back into the graph. He re-reads the CA 19-9 section three times — that node's weight increases. He clicks "explain more" on bilirubin — that topic gets added to his interest graph with a high weight. He never opens the fat stranding section — it stays suppressed in future reports.

By report 6, the Interest Graph knows James deeply: he cares about tumor markers and vascular status, he finds surgical resectability language confusing, and his caregiver reads the "background" section after him. The ranker gets sharper with every cycle.

📈

Weight increases

CA 19-9, tumor size, FOLFIRINOX response — James engages heavily. These get surfaced first, always.

🔕

Noise suppressed

Fat stranding, routine neutrophil counts — James never engages. The ranker learns to filter these below the threshold.

🧩

Memory prevents repetition

CA 19-9 was explained in session 1. The memory pack prevents Pantory from re-explaining it from scratch in session 4.

6User Stories

Three perspectives on the same workflow — patient, caregiver, and oncologist.

User Story 1 · The Patient

"As James, I want to understand what changed in my latest report without having to decode medical jargon — so I can have an informed conversation with my oncologist tomorrow."

What
Ranked, plain-language explanation of the 3 most important findings from his cycle 4 CT + labs.
When
Immediately after uploading the report, the night before his oncology appointment.
Why it helps
James doesn't have to re-learn what CA 19-9 means. The SDK skips what was explained before and leads with what changed. He arrives at his appointment with specific, informed questions.
SDK role
Memory Pack skips re-explained terms. OpportunityRanker leads with the CA 19-9 drop. Interest Graph knows James tracks this marker obsessively.
User Story 2 · The Caregiver

"As James's wife Linda, I want to know if there is anything urgent in this report that requires action before his next appointment — so I know whether to call the oncologist today."

What
A clear signal: "call now" vs. "mention at appointment" vs. "nothing to act on."
When
Same session — Linda reads the report alongside James, or on her own later that day.
Why it helps
The timeliness signal in the ranker explicitly flags critical vs. non-urgent findings. Linda doesn't need medical training to understand the priority triage — the SDK has already done it.
SDK role
Timeliness scoring (20% weight) distinguishes the bilirubin elevation (mention at appointment) from a hypothetical new hepatic lesion (call today). Caregiver sees the same ranked output as James.
User Story 3 · Longitudinal Tracking

"As James, I want to see whether my CA 19-9 trend over 4 months suggests my treatment is working — so I can feel informed and emotionally grounded about my prognosis."

What
A treatment response trend across all 4 reports — not just the latest one in isolation.
When
Available after 2+ report uploads. The Interest Graph stores historical values as entity attribute history.
Why it helps
No other tool does this. An LLM reading report 4 in isolation cannot tell James that his CA 19-9 has dropped 89% from its peak. The graph remembers. That number is life-changing information for someone with PDAC.
SDK role
Interest Graph stores value history on entity nodes (CA 19-9: [2847, 1240, 647, 312]). The ranker's novelty signal detects the trend direction. Memory Pack prevents re-explaining the trend James already understands.
User Story 4 · Critical Event

"As James, if a new finding appears that could change my treatment plan, I want to know immediately — not buried on page 3 of a summary."

What
Immediate prominent alert if a new hepatic lesion, peritoneal seeding, or SMA involvement appears for the first time.
When
The moment the ranker detects a new critical finding (timeliness: 1.0, novelty: 1.0) — it overrides the normal ranked output and surfaces this first, at the top.
Why it helps
A flat LLM summary can bury a new metastatic finding in paragraph 4. The ranker's timeliness × novelty combination makes this mathematically impossible — it will always score highest.
SDK role
OpportunityRanker detects score ≥ 0.90 + timeliness = 1.0 → triggers critical alert path. Memory Pack confirms: this entity has never appeared before, novelty = 1.0. Fatigue gate overridden for critical-class findings.
