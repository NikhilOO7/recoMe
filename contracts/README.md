# API contracts — shared fixtures

Canonical server responses, generated by REAL cloud code paths and asserted
on both sides of the wire:

- `cloud/src/__tests__/contracts.test.ts` (vitest) — regenerates each fixture
  from the actual handler/service and fails if it no longer matches. To
  intentionally change a contract: `UPDATE_CONTRACTS=1 npx vitest run
src/__tests__/contracts.test.ts`, review the diff, commit.
- `extension/src/shared/__tests__/contracts.test.ts` (jest) — assigns the SAME
  fixtures to the client types; ts-jest fails compilation if the client's view
  of the API drifts.

Why this exists: two shipped bugs came from hand-written client types
diverging from real responses (the invented `subscription` object on
AgentInfo; the flat CardScore fields). This harness makes that class of bug
fail in CI on whichever side moved.
