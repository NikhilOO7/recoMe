SDK Modules

Four Modules.
One Personalization Stack.

Every module feeds the same per-user graph. Add one or all four — they compound.

▲ Interest Graph

InterestGraph

A per-user entity graph with typed, weighted edges. Grows every session. No retraining — weights update in real-time as the user interacts.

  • Typed edge vocabulary — interested_in, confused_by, tracks, has_condition, blocked
  • Weights decay, strengthen, and branch automatically with each session
  • Vertical-calibrated defaults on day one — cold start solved
  • Works from session 1 with no historical data required
interested_in[w:0.95] tracks[w:0.88] has_condition[w:1.0] confused_by[w:0.42] blocked[w:0.85]
sdk.interestGraph.query(userId)
// → { nodes: [...], edges: [...], updatedAt }
△ OpportunityRanker

OpportunityRanker

4-signal scoring against this specific user's graph. Returns a ranked list with scores and human-readable reasoning. Threshold filter removes noise before your LLM ever sees it.

  • Interest Match — 35%: alignment with user's highest-weight graph nodes
  • Benefit Clarity — 25%: how actionable the finding is for this user
  • Timeliness — 20%: recency and change velocity of the content
  • Novelty — 20%: delta from what the user already knows (via MemoryPack)
sdk.opportunityRanker.rank(findings, userId)
// → [{ item, score, signals, reasoning }]
■ Memory Pack

MemoryPack

Short-term and mid-term memory cards per user. Tracks what concepts were explained, which sections were re-read, and what questions were asked. Prevents re-explaining what the user already knows.

  • Short-term: session-scoped context (concepts explained this session)
  • Mid-term: cross-session cards (persisted, versioned, queryable)
  • Feeds directly into OpportunityRanker's Novelty signal
  • Surfaces as structured context for your LLM prompt construction
sdk.memoryPack.load(userId)
// → { session: [...], crossSession: [...] }
sdk.memoryPack.write(userId, card)
□ Profile Extractor

ProfileExtractor

Pluggable specialty module registry. One SDK core — infinite domain modules. Each module parses domain-specific documents and writes structured findings into the Interest Graph.

  • Module registry: plug in oncologyModule, contractModule, earningsModule, and more
  • Extracts structured entities and edge data from unstructured docs
  • All modules feed the same InterestGraph — no duplicate data layers
  • Build your own module with the Module SDK spec in under a day
sdk.profileExtractor.use(oncologyModule)
sdk.profileExtractor.parse(document, userId)
// → 12 structured findings → written to graph

5
Delta detection — v3 compared against v2 entity history

3 changed clauses identified across 18 total. Indemnification cap changed from $2M to $500K — Rachel's highest-weight node. IP ownership clause now includes "work made for hire" language that was absent in v1 and v2. Governing law changed from New York to Delaware — Rachel's blocked category.

7

The indemnification change and the IP clause. Both highlighted inline in the document viewer. The jurisdiction change — 15 unchanged provisions and the boilerplate — never surface. Rachel goes directly to what matters.

Outcome

Rachel reviews the contract in 6 minutes instead of 45. She catches the indemnification change from $2M to $500K — a shift that would have cost her client $1.5M in an adverse claim scenario. The SDK's delta detection found it before she read page one.

Risk Assessment

Three Real Risks.
Three Concrete Mitigations.

We've identified the risks investors will ask about and built them into the product roadmap and go-to-market.

▲
Cold start at the customer level

The user interest graph is thin in the first 1–2 sessions. Rankings have lower signal-to-noise before the graph has depth. Mitigation: Vertical-calibrated default weights derived from aggregate anonymized data across all users in a domain. A new oncology patient starts with meaningful edge weights from day one, not an empty graph. Cold start at user level is solved by day-1 defaults.

△
Big tech competition

OpenAI or Google could add a preference graph layer to their APIs within 12–24 months. Mitigation: HIPAA BAA and SOC 2 Type II certifications are a hard moat in healthcare and legal — hyperscalers won't get those fast. Switching costs from customer-specific graph data compound with every session. Customers who've built 18 months of user interest history won't migrate to a new provider. The moat is the data, not the algorithm.

■
Enterprise sales cycle length

HIPAA-regulated enterprise deals take 6–9 months to close. Long cycles strain runway and create revenue timing risk. Mitigation: The self-serve Growth tier at $499/month creates a pipeline of 50–100 paying customers that requires zero sales motion. Growth customers convert to Enterprise when their user base scales. This structures the sales funnel so that enterprise deals close on top of existing ARR, not instead of it.
